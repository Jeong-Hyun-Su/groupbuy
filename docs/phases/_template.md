# Phase N — <한 줄: 무슨 문제를 무엇으로 증명했나>

> Phase 가 끝나면 이 틀을 복사해 `docs/phases/phase-N-<주제>.md` 로 채운다. 1~4장은 **측정 전에** 쓴다.

## TL;DR
- 문제: <1줄>
- 결과: <핵심 수치 2~3개. "0건" 증명 포함>
- 선택: <최종 선택과 한 줄 이유 → ADR 링크>

## 1. 문제
상황, 왜 위험한가(돈·사용자 영향), 재현 방법(테스트·스크립트 링크). 앞 Phase 의 측정에서 드러난 한계가 동기라면 그 기록을 링크한다.

## 2. 성공 기준
지키는 불변식(R1~R8 중 해당)과 검증 방법(SQL·테스트), 수치 목표.

## 3. 가설과 후보
후보마다 "이러면 이렇게 될 것이다"를 **측정 전에** 적는다.

## 4. 실험 설계
환경(머신, 컨테이너 자원 한도, DB·풀 설정), 시나리오 표, 변수, 측정 지표, 반복 횟수(3회, 중앙값).

## 5. 결과
시나리오 × 후보 결과표, 그래프, 원자료 링크(`docs/loadtest/…`). **예측과 다른 점**을 따로 적는다.

## 6. 결론과 트레이드오프
언제 무엇을 쓰나, 이 선택의 비용, 운영이라면 다르게 할 점.
