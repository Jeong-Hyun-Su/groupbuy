# ADR-003: 정가 선결제 후 마감 시 차액 부분취소

- 상태: Accepted
- 날짜: 2026-09-16
- 관련 Phase: 1 (승인), 3 (환불 파이프라인)

## 맥락
ADR-002 에 따라 참여 시점에 최종 금액을 모른다. 참여 의사를 어떻게 결제로 묶을지 정해야 한다.

## 선택지
1. **정가 선결제 → 마감 시 차액 부분취소** — 참여 의사가 결제로 확정됨. 국내 PG 부분취소 API 표준 지원 / 환불 건수 = 참여자 수. 환불 파이프라인 신뢰성이 핵심 품질이 됨
2. **사전승인(auth) → 마감 시 확정 금액 매입(capture)** — 환불 없음 / 국내 카드 결제에서 auth/capture 분리가 제한적. 승인 유효기간 문제
3. **마감 후 확정 금액으로 결제 요청** — 환불 없음 / 마감 후 결제 이탈 → 확정 인원이 무의미해짐. 인원 조작 가능

## 결정
1번. 참여 시 정가로 승인하고, 마감 시 `refunds(reason = TIER_ADJUST)` 를 참여자 수만큼 생성해 부분취소한다. 무산 시 `DEAL_FAILED` 로 전액 취소.

## 근거
- 3번은 도메인 자체를 무너뜨린다. 2번은 PG 현실에 맞지 않는다.
- 1번의 비용(대량 환불)은 정확히 이 프로젝트가 증명하려는 역량(멱등성, 재시도, 원장 대조)이다.

## 결과
- 얻는 것: 참여 = 결제 확정, PG 표준 API 사용
- 잃는 것: 마감 후 환불 N건. Phase 3 이 가장 긴 이유
- 필수 조건: 환불은 멱등해야 하고(R6), 실패는 재시도 후 사람에게 넘어가야 하며(MANUAL_REQUIRED), PG 기록과 대조되어야 한다(R7)
