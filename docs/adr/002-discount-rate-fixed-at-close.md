# ADR-002: 할인율은 마감 시점 최종 인원으로만 확정한다

- 상태: Accepted
- 날짜: 2026-09-16
- 관련 Phase: 1

## 맥락
"모인 인원에 따라 할인율이 올라간다"를 구현할 때 각 참여자의 가격을 언제 확정할지 정해야 한다.
티어 경계(예: 49명 → 50명)에서 동시에 들어온 요청을 어떻게 다룰지가 걸려 있다.

## 선택지
1. **참여 시점의 인원으로 개인별 확정** — 결제 금액이 즉시 확정되어 환불 불필요 / 늦게 온 사람이 더 싸게 사는 역설. 티어 경계에서 원자적 "카운트+티어 판정"이 필요해 동시성 문제가 커짐. "함께 모아서 함께 싸게"라는 도메인 의도와 어긋남
2. **마감 시점 최종 인원으로 전원 동일 확정** — 공정하고 도메인 의도와 일치. 참여 시점엔 인원만 세면 되므로 동시성 문제가 카운팅 하나로 좁혀짐 / 참여 시점에 최종 금액을 모름 → 선결제·환불 구조 필요

## 결정
2번. 참여 시점의 할인율은 **예상(projected)** 으로만 표시하고, 마감 시 `Deal.finishClosing(confirmedCount)` 가 전원에게 동일한 **확정(final)** 할인율을 부여한다.
`Deal` 애그리거트가 이 규칙(R3)을 책임진다.

## 근거
- 티어 경계 경쟁 조건이 도메인 규칙으로 해소된다: 49번째와 50번째가 동시에 들어와도 둘의 가격은 마감 시 같다.
- 참여 API 는 "정원 안에 들어갔는가"만 답하면 되어 Redis 원자 연산 하나로 충분하다 (ADR-004).

## 결과
- 얻는 것: 단순한 동시성 모델, 공정성, 도메인 일치
- 잃는 것: 결제 시점 금액 불확정 → ADR-003 의 선결제·차액 환불이 필수가 됨
- 사용자 안내: 결제창에 "정가 결제 후 마감 시 차액 자동 환불" 을 명시해야 한다
